# Radio Friday 双端视觉与体验系统

Radio Friday 是中文陪伴聊天、直播与小说阅读网站。桌面采用中性黑灰白的 `theme-graphite`，手机采用暖黑、香槟金及独立页面组合；雨夜摄影继续使用独立场景变量。桌面公共布局与侧栏通过中性明暗渐变分区，登录／注册及独立场景保留各自设计。整个前端使用 **Tailwind CSS v4**。

## 架构与共享边界

手机网页通过独立 workspace 包与桌面分开开发，仍在同一 Next.js 站点部署。后续小程序采用 Taro + React，复用业务核心并自行实现平台适配与页面；本次不创建小程序应用，不改变后端认证协议。

| 包 | 职责 |
| --- | --- |
| `apps/web` | Next.js 路由、服务端取数/Server Actions、认证、桌面界面、稳定业务宿主和浏览器/LiveKit 资源 |
| `@my-platform/mobile-web` | 手机页面组合、导航、底部操作面板、消息输入和手机专属交互状态 |
| `@my-platform/web-ui` | 共享 Sheet、Select、头像、场景横幅、标题、加载占位和视口订阅 |
| `@my-platform/client-core` | 业务 store 工厂、actions、selectors、校验和注入式服务契约；`/react` 为独立 React 绑定入口 |
| `@my-platform/shared` | 共享业务数据类型与接口契约 |

依赖由应用指向包；UI 包不反向引用应用或 Next.js。导航链接、服务端内容及优化图片通过 props/slots 注入。共享核心使用 Zustand vanilla 和 query-core，不直接调用浏览器资源或导入 LiveKit；平台行为由宿主注入。`pnpm check:client-boundaries` 检查这些边界。

- 同一个 Next.js 工程、同一组路由、登录态和后端 API。根布局负责解析账户；普通主 Tab 复用已解析的账户，详情、阅读与管理页继续负责服务端内容和权限检查，不能为双端视图复制认证或权限判断。
- 业务控制层负责查询、缓存、权限、提交和实时连接；其下才是桌面／手机页面组合。`useCompanionHome`、`useLiveLobby`、`useConversation`、`useLiveRoom` 和 `useLiveVoice` 不随视图切换重新挂载。
- `useViewport` 是客户端页面的统一视口入口：小于 768px 为手机，其余为桌面。服务端与客户端首次渲染均返回未知视口，复杂页面在内容区显示对应布局的加载占位，四个主 Tab 使用内容骨架，公共导航与页面外框保持可用，避免 hydration 不一致或先展示桌面布局。
- `AppShell` 的桌面侧栏与手机底栏是没有业务副作用的导航组件。`BrowsingPages` 稳定宿主按已提交 pathname 直接呈现四个主 Tab：陪伴目录按需挂载后保留，其他三个仅在当前路由挂载并从缓存恢复；主 Tab 的 page/loading 不重复渲染内容或覆盖路由骨架。详情、阅读与编辑继续由实际路由 children 服务端渲染，书架统一使用客户端查询。
- 实时聊天室的连接、草稿和媒体节点位于稳定的组件层级中。手机的成员／连麦面板独立组合，舞台和聊天记录不因横竖屏切换而重建。
- 通用按钮、头像、书封、消息气泡、状态提示和表单字段共享；手机页面信息顺序、导航、筛选和操作面板由 mobile-web 独立组合。连接、会话和媒体元素保留稳定层级，不通过复制后隐藏实现双端页面。

## 客户端状态管理

客户端业务状态优先放在 `packages/client-core/src` 的 Zustand store 中；`apps/web/src/stores` 保留浏览器适配、Provider 和网页交互组合，手机专属交互状态放在 `packages/mobile-web/src/stores`。组织方式参考 [LobeChat 的业务 store 与 slice 组合](https://github.com/lobehub/lobehub/blob/main/src/store/chat/store.ts)：区分初始状态、action、selector 和组合入口；复杂域拆 slice，小型 store 可以同文件组织。业务组件订阅 selector，通过 action 更新状态；组合多个字段的 selector 使用 `useShallow`，避免每次读取返回新对象导致重复渲染。需要在异步回调中读取最新值时使用当前实例的 `getState()`；不得用它代替视图订阅。

业务 action 应包含校验、权限与并发门禁、请求编排、错误恢复、重试 ID、原子状态切换和 Query 缓存更新，不只提供 setter。网络协议放在 services，浏览器／SDK 资源通过适配函数传入 action，不存进 store。组件负责渲染、路由和资源生命周期，避免再用一组 setter 在组件内重建业务流程。

所有业务 store 通过 `createDomainStore` 组合 `subscribeWithSelector`。参考 [LobeChat 的草稿订阅](https://github.com/lobehub/lobehub/blob/main/src/features/ChatInput/hooks/useChatInputDraft.ts)，跨状态联动优先使用 selector subscription：侧栏偏好保存、验证码倒计时、筛选后的查询取消和滚动、身份选择刷新、验证完成后的焦点、关闭房间弹窗、连麦授权撤销、消息滚动和通知过期。订阅在宿主 effect 内绑定并返回 unsubscribe；定时器和 animation frame 一并清理，支持 Strict Mode 重绑。只有需要初始化外部资源时使用 `fireImmediately`；复合 selector 应使用 equalityFn。视图仍使用 `useStore(selector)`，不得通过手动订阅再维护一份 React 状态。用户主动提交仍调用 action，不能由订阅隐式发起继承、创建房间等写操作。

| Store | 管理范围 | 生命周期 |
| --- | --- | --- |
| `app` | 侧栏折叠与客户端布局初始化 | 账户 Provider；只有侧栏偏好写入 localStorage |
| `browse` | 个人页标签、直播搜索与筛选、最近陪伴 URL | 账户 Provider；只保留当前文档内浏览状态 |
| `chat` | 按会话区分的输入草稿 | 账户 Provider；同账户路由切换保留，退出或换账户销毁 |
| `chat/conversation`、`chat/auto-reply`、`chat/preferences` | 连接错误、发送中的消息、失败重试请求 ID、设置提交反馈 | 当前会话；以 conversationId 为 key |
| `auth`、`auth/transition` | 手机验证、注册资料、密码输入、倒计时、字段错误、认证页退出状态 | 当前表单／认证过渡宿主；不持久化 |
| `companion`、`catalog` | 已应用筛选、默认标签、独立筛选草稿与手机搜索 | 陪伴稳定宿主／筛选编辑器；已应用条件随 Tab 保留，关闭筛选弹层丢弃未应用草稿 |
| `identity` | 身份选择、确认快照、性别输入 | 当前页面，账户切换时一并销毁；个人页标签由 browse 管理 |
| `live/lobby`、`live/room`、`live/voice`、`live/chat`、`live/stage` | 创建流程、房间会话、媒体状态、连麦、消息、未读与舞台选择 | 当前大厅／房间；以 roomId 为 key，离开／重连清理会话状态；大厅搜索与筛选由 browse 管理 |

Store 由 `useStoreInstance` 在稳定宿主内创建，工厂不启动网络连接或计时器。根 `Providers` 已按 accountId 设置 key；桌面和手机消费同一业务层实例，窗口尺寸变化不会创建第二套 store 或连接。遵循 [Zustand 的 Next.js 实例隔离建议](https://zustand.docs.pmnd.rs/learn/guides/nextjs)，禁止模块级可变账户、表单或房间单例，避免服务端请求间共享数据。React Context 只负责注入 store 实例或导航／动画命令，不另存一份业务状态。

React Query 继续管理角色目录、会话列表、历史消息、自动回复设置、身份继承和房间列表等接口数据；不将查询结果同步复制到 Zustand。URL 中的 `view`、会话和路由信息仍由 Next.js 路由管理。原生表单提交生命周期继续使用 `useActionState` / `useFormStatus`。小说书架由账户作用域 React Query 管理，详情、阅读和管理内容仍由服务端渲染。小说写操作继续使用 Server Action 和原生表单；客户端表单适配器标记书架查询失效，提交完成后再次失效以覆盖写入与提前返回的竞态，不复制详情或章节缓存。

DOM、WebSocket、LiveKit Room/Track、AbortController、计时器、滚动与焦点快照留在 refs/effects 中，保持原来的关闭和释放路径。允许局部 React 状态的范围是：通用 Select 的展开、选项搜索、键盘活动项及原生有效性；说明弹层和账户菜单的显示；手机号遮罩；背景轮播和个人页标签指示条的纯动画状态；瀑布流测量；路由滚动恢复期间的绘制就绪状态；`CompanionChatRoute` 的宿主注册及测量快照展示状态；LiveKit Track 的视图绑定。这些属于控件自身或浏览器资源状态。性别、手机号、密码、筛选值等业务输入由所属 store 控制。

密码、验证码、验证票据、房间令牌和账户草稿只在内存中存在，不进入 localStorage、devtools 或 window 全局。异步结果写回创建它的实例；手机输入版本变化后，旧验证响应不得恢复票据。发送成功只清除与原发送内容一致的草稿，失败重试复用请求 ID。直播消息去重并限制历史长度；断开后清理房间权限、连麦批准、设备状态和消息草稿。

## 设计变量

`apps/web/src/app/theme.css` 是唯一 token 入口；`globals.css` 导入 token 并提供共享组件样式，通过 `@source` 扫描 mobile-web 与 web-ui 的 Tailwind 类名。页面优先使用 JSX 的 Tailwind 工具类；共享样式用 `@apply`，功能样式表用 `@reference` 引用全局入口。颜色不得写进业务组件。

下表为手机及现有 `theme-night` 的变量：

| 用途 | 值 | 工具类 |
| --- | --- | --- |
| 页面背景 | `#1B1B19` | `bg-canvas` |
| 面板 | `#141413` | `bg-panel` |
| 次级表面 | `#262623` | `bg-surface-soft` |
| 悬停／选中表面 | `#33322E` / `#3B3933` | `bg-surface-hover` / `bg-surface-selected` |
| 正文 | `#F3F1EC` | `text-ink` |
| 次要文字 | `#B9B5AD` | `text-muted` |
| 提示文字 | `#AAA59C` | `text-faint` |
| 分隔线／控件边界 | `#41403B` / `#777269` | `border-line` / `border-control` |
| 主操作／反色文字 | `#DFBC89` / `#262522` | `bg-action text-on-action` |
| 品牌／焦点 | `#DFBC89` | `text-accent outline-focus` |
| 阅读背景 | `#1D1C19` | `bg-reading` |

桌面 `theme-graphite` 复用相同语义工具类：背景 `#111111`、面板 `#181818`、次级表面 `#242424`、悬停 `#2C2C2C`、选中 `#343434`、边界 `#383838`、控件边界 `#737373`、正文及主操作 `#F5F5F5`、辅助文字 `#A3A3A3`，主操作反色文字为 `#181818`。品牌强调与焦点使用中性灰白，不使用暖白或棕色；公共背景氛围光按统一设计使用低饱和紫色。仅在 768px 起应用，手机继续继承根节点的 `theme-night`。

根节点与局部 `theme-night` 使用同一套变量，不随系统明暗偏好变化。图片使用独立 `photo-*` token，成功、警告、错误使用各自语义色及 soft/line 配套变量，始终配文字说明。

- 字标采用 Georgia（`font-brand`），中文采用苹方／微软雅黑。桌面标题 28–32px，手机标题 24px，正文 14–16px，辅助文字至少 12px；阅读正文 18px、1.9 倍行高、最大宽度 680px。
- 4px 间距体系；控件圆角 10px、卡片 16px、摄影横幅 24px。桌面公共内容容器使用共享 `page-shell`，最大宽度 1280px，在侧栏之外的可用区域内居中；视口达到 1280px 时左右内边距为 64px，较窄视口沿用自适应边距。陪伴、直播大厅、小说和「我的」首页统一使用该容器，侧栏展开宽 236px，收起宽 80px。
- `theme-night` 的金色用于主操作、焦点和少量品牌细节；列表、面板通过实色表面与留白分层，不叠加大面积发光效果。
- 摄影使用现有素材。`SceneBanner` 负责桌面 260px 横幅和紧凑场景；手机最近聊天没有横幅。新增场景没有自动轮播。
- 通用图标使用 lucide-react，1.75–2px 线宽；`RadioMark` 使用 AudioLines。桌面主导航使用自绘 28px SVG 图标：爱心对话、收音机、书签书页、圆形账户；统一继承语义文字色，手机保留现有图标。

## 双端页面与导航

| 页面 | 桌面 | 手机 |
| --- | --- | --- |
| 陪伴 | 场景横幅、目录、最近聊天侧栏 | 最近聊天优先，分段切换最近／发现，紧凑人物列表；移除占用首屏的大横幅 |
| 人物目录 | 常驻筛选与多列虚拟列表 | 单列虚拟列表、搜索、筛选底部弹层 |
| 聊天 | 对话与宽屏设置侧栏 | 全屏对话、自适应高度输入与独立发送按钮，设置从底部打开 |
| 直播大厅 | 场景横幅、房间目录、创建面板 | 列表优先，开播入口打开底部表单 |
| 直播房间 | 舞台与互动侧栏 | 紧凑房间标题与舞台，持续显示聊天，成员和连麦使用底部面板 |
| 小说 | 摄影与书封网格 | 书封与简介组成阅读列表，创作操作独立呈现 |
| 阅读 | 居中正文 | 单份服务端正文，底部提供上一章／目录／下一章 |

「我的」采用宽幅个人主页，使用公共内容容器。冷色月夜海面作为页面顶部背景，横向铺满内容视口、贴顶，无圆角、外框或投影。通过 alpha mask 向下透明渐隐，桌面左侧也淡入侧栏背景，露出页面自身底色，不叠加不匹配的黑色底板。资料区位于背景下半部，头像和文字使用常规语义 token；手机号隐藏时显示划线眼睛，明文时显示普通眼睛，按钮可访问名称描述下一步操作；不重复展示「我的」标题。手机保留原暖色主题。Tab 与下方内容直接使用页面背景，不加外层底色、边框或阴影，导航和内容共用 16px／24px 内边距，内部会话入口使用轻量次级表面而非多重边框。会话卡片与 AI 身份入口悬停时保持底色，通过贴近边缘的低饱和青灰、淡紫微光反馈，光晕半径 8px、透明度 6%–7%，避免明显亮框与大范围扩散，使用 theme.css 中的共享 shadow-card-hover-glow token，200ms 渐入渐出；键盘聚焦同样显示柔光并保留焦点轮廓，减少动态效果时取消过渡。通过「最近聊天」「AI 身份」两个等宽、同字重的标签切换内容；选中项使用 3px 的青蓝—紫色—粉色渐变滑动下划线及轻微柔光，渐变与柔光 token 统一定义在 theme.css；这是用户指定的局部彩色强调，其他桌面控件保持黑灰白。桌面不显示独立胶囊底色；手机使用分段式按钮背景标明选中项。桌面切换时指示条在两个标签间移动，并带短暂拉伸、轻微回弹；首次加载不播放动画，快速反向切换从当前位置接续，减少动态效果时即时定位。下划线仅表示选中状态，悬停只改变文字色；支持方向键、Home/End 与可见焦点。面板外沿与资料区使用同一个 page-shell 对齐线。最近聊天从现有 matches 接口读取，在内容标题旁以紧凑圆角徽标显示真实数量，使用等宽数字、低对比底色和细边框，并展示会话入口，保留加载、失败重试、空状态。发现入口仅保留内容标题右侧的「认识新朋友」，封面与空状态不再重复提供聊天／发现按钮。AI 身份区域沿用角色选择、继承规则和最终确认流程；已继承时展示真实角色与回复入口。不添加虚构的粉丝、等级、作品数或无功能的设置入口。桌面平台互动说明和退出登录保留在账户菜单中，手机个人页提供对应的底部操作入口。桌面侧栏在登录后保留四个直接入口；访客只显示陪伴、直播和小说，账户入口集中在底部的「登录 / 注册」。导航行高至少 56px、胶囊圆角、16px 半粗文字；选中态使用中性表面及底部轻微柔光，不增加多级菜单。桌面侧栏底部不加分隔线，账户入口距离视口底部 32px，只保留一个账户入口：40px 实色头像配姓名和「账户与身份」，不显示箭头。鼠标悬停 120ms 后打开右侧约 300px 宽的账户浮层，点击、触控和键盘也可展开，不跳转陪伴页；浮层使用原生 auto Popover 进入浏览器顶层，避开侧栏滚动裁切，浮层左边与账户入口右边保持 8px 间距，底边严格对齐账户行，最大高度按账户行底边至视口顶部的可用空间计算，短屏内部滚动。「我的」（/me）保留在主导航，浮层只包含「拥有一个 AI 身份」（/choose-identity，说明为「以角色身份回复其他用户」）、平台互动说明和退出登录；已继承身份时第一项显示角色名字及「以此身份回复消息」，进入 /operator。继承页面继续保留不可更换等规则和最终确认。退出登录复用现有服务端 action。悬停打开不抢焦点，鼠标离开入口和浮层后延迟 250ms 关闭，经过两者间隙不会立即收起；点击或键盘打开时聚焦首个链接，Escape 关闭，焦点原本在浮层内时返回触发按钮，点击外部、焦点离开、点击链接、切换路由或调整视口时关闭。悬停用表面和文字颜色反馈，不使用下划线。长名称省略但保留完整可访问名称。

## 认证与组件状态

### 路由与数据加载

主导航点击后立即高亮目标，并以轻量进度提示表示路由等待，不覆盖或禁用整页内容。URL 提交前的临时状态放在账户作用域的 app store，只有目标地址与递增导航标识，不持久化。Next Link 的 pending 状态负责结束跟踪，旧导航不得清除新导航；实际 `aria-current` 以已提交 URL 为准。缓存命中时不设置最短等待时间；失败、重定向和浏览器历史变化都清理过期状态。重复点击当前 Tab 不重新请求，也不强制置顶。认证关闭动画继续由原宿主管理。

根布局先读取本地会话 Cookie；有会话时将远程账户解析放入 Suspense，等待期间输出正确主题、桌面／手机导航及目标页面的真实展示框架：个人页封面、资料位置与页内 Tab；陪伴、直播及书架的标题、横幅与列表工具栏。账户相关控件在解析完成前禁用，骨架仅落在头像、资料或列表等待区域，不把内容替换成独立的通用账户加载块，也不闪现游客账户入口。启动框架与正常页复用展示组件，不挂载业务查询、账户 store 或实时连接。账户解析完成后将同一用户信息交给按账户 ID 隔离的 Provider，四个一级页面直接复用。访客不请求 `/me`；认证页首次加载继续保留完整外框。

陪伴「最近聊天」的启动展示与正常页面共用 `RecentConversationsFrame`，从第一屏就保留标题、数量位置、禁用的刷新按钮、聊天骨架和底部入口。账户解析和聊天请求之间保持同样的区域尺寸，避免先出现空框、随后补入加载内容。手机明确选择最近聊天时沿用相同结构；未指定标签时继续等待会话结果决定默认内容。

加载按区域设计，四个主 Tab 首次无数据时使用与真实内容对应的骨架：陪伴目录按容器宽度展示头像、资料、介绍和操作占位；直播列表沿用房间卡片列宽与 16:9 封面；书架沿用双列手机／自适应桌面网格与 3:4 书封；「我的」保留封面和个人页 Tab，在头像、姓名、手机号及聊天网格位置显示骨架。账户解析、视口初始化和首次接口等待共用同一套展示组件，避免阶段切换时闪出转圈黑块或空白列表。骨架用共享 `SkeletonRegion` / `SkeletonBlock` 和语义表面色，留在正常文档流内，不覆盖导航、标题、筛选或页内 Tab；加载说明供读屏使用，装饰占位不参与交互，轻微明暗动画在减少动态效果时关闭。详情、阅读、身份、工作台及表单继续保留对应页面结构并使用局部 `LoadingPlaceholder`；聊天和直播连接等待留在各自消息／连接区。已有缓存直接显示，不因主 Tab 往返或直播后台轮询重新出现骨架；手动刷新仍只在触发按钮显示进度，失败保留内容并在本区域提供重试，不使用虚构进度。

普通主 Tab 查询统一使用 `staleTime: Infinity`、`gcTime: Infinity`，关闭聚焦和网络重连触发的普通列表刷新；每个账户在当前文档内保留 React Query 缓存，不写持久存储。列表提供定向刷新入口，自己的操作通过缓存更新或主动失效反映结果，不调用整站 `router.refresh()`。浏览器刷新重新取数；退出或换账户销毁缓存、浏览状态和滚动快照。最近聊天共用一个账户级 WebSocket，陪伴与「我的」共享列表，HTTP 响应不得覆盖后到的实时快照；聊天连接仍由会话宿主管理。打招呼等待期间离开陪伴后，成功结果仍更新当前账户的会话列表，但不再自动进入聊天；退出账户后，旧操作不得写回缓存或导航。已登录会话的查询返回 401 时，根错误处理合并并发核验，专门请求一次 `/me`：同一账户核验成功直接更新账户查询，页面和导航共享该结果；核验服务暂时失败或返回 403 时保留已有身份，后续操作可再次核验。确认 401 后清除私有缓存并以新文档进入登录页，确认换账户后重新加载文档，销毁旧账户资源。普通业务请求返回 403 只显示当前操作的权限错误，不触发核验或清除账户。

直播大厅和房间详情通过同源 `/ws/rooms` 接收共享状态快照，首次连接、断线重连后同步完整状态，不运行固定 5 秒 HTTP 轮询。大厅允许游客订阅公开列表，管理权限按当前账户计算；桌面／手机视图共用连接宿主。推送写入 React Query 前取消旧 HTTP 请求，避免旧响应覆盖新状态；离开页面或账户切换时销毁连接与重连计时器。普通详情读取不触发 LiveKit 核验或清理；手动刷新使用受限的显式核验接口。连麦依赖 LiveKit 属性和权限事件更新，进入、重连与用户操作时进行权威查询，不定时刷新。创建和关闭仍原子更新缓存，直播间标题来自详情快照。小说详情认证与内容保持并行；写操作返回书架后定向更新。聊天入口复用已有 match，悬停／聚焦只预取 HTTP 消息。

直播大厅右侧房间面板在账户初始化和首次房间查询期间共用标题、说明骨架，并按创建表单的文字排版保留空间；确认房间状态后才显示「创建直播间」或「我的直播间」，避免刷新时提前展示房间归属。已有缓存的后台更新不显示这组骨架。

滚动、可见内容锚点与焦点快照由账户作用域稳定宿主的 refs 保存，首次访问置顶，切 Tab 与前进后退恢复。先在 `useLayoutEffect` 中同步恢复滚动；尺寸变化或需要后续测量校正时，仅临时隐藏内容宿主，位置稳定后显示，导航始终可用。陪伴目录在恢复期间暂停自动分页，隐藏期间保留上次的桌面／手机呈现。同一视口恢复原位置；尺寸变化时，陪伴目录、书架、最近聊天和直播列表优先恢复原内容锚点。普通列表通过稳定的 `data-browse-anchor` 标识内容，快照只保存标识和偏移，不持有卸载后的 DOM；内容已移除时回退到合法范围内的原滚动位置。URL 参数仍由路由管理，主导航回陪伴使用上次的 `view`。聊天房间、LiveKit、认证和编辑表单不纳入页面保活，不因保留浏览状态延长连接或敏感草稿生命周期。

认证轮播共享一套场景与计时器，用 picture/source 在 760px 分界选择现有手机／桌面素材，首张完成后只预载下一张。允许其局部 React 状态保存场景、已请求／已加载图片和减少动画偏好，均属于动画与浏览器资源状态；不保存业务输入。减少动画时停止自动轮播，手动切换仍可用。

登录／注册延续原有摄影和布局，统一消费暖黑金色 token。保留 5 秒场景轮播、手动选择、减少动态效果，以及原有手机背景；不改认证和身份流程。注册先验证手机号，再设置密码、昵称和性别。

登录与注册共用 `(auth)` 路由布局，客户端切换时只替换表单，外框、品牌与轮播保持挂载，场景及播放进度持续。认证页在首屏加载时也不进入公共侧栏布局。外框右上角提供 44px 关闭入口，关闭后以访客身份进入陪伴首页，并替换历史记录，避免返回时重新打开刚关闭的认证页。关闭采用约 380ms 的登录页轻微缩小、淡出与首页原位淡入动画。等待实际公共布局挂载并恢复侧栏收起状态后再开始过渡，不对首页及包含固定导航的容器施加缩放或位移；不支持视图过渡时同样使用首页原位淡入，减少动态效果时直接切换。完成后将焦点移至首页主内容。桌面外框高度由视口决定，表单内容超出时只滚动左栏；手机继续使用原有随内容展开的布局。

所有页面和组件的 hover 均不得显示下划线，包括导航、普通链接、按钮、帮助和说明入口。使用文字色、背景色或边框色提供悬停反馈，保留可见键盘焦点；不要添加 `hover:underline` 或通过伪元素模拟悬停下划线。

职业和性别下拉选择统一复用 `components/select.tsx`，不各自实现菜单。可见控件使用主题化按钮和 listbox，不使用原生 `<select>` 弹出系统菜单；隐藏的原生字段仅用于表单提交与必填校验。菜单通过 Popover 进入浏览器顶层，继承所在区域的主题 token，并按可用视口定位和限制高度，避免被滚动容器或 Sheet 裁切。长职业列表支持搜索和内部滚动；保留方向键、Enter、Escape、Tab、选中标记、点击外部关闭及焦点恢复。验收必须展开菜单，覆盖再次打开、应用筛选后的重建、刷新和手机弹层场景，不能只检查收起时的输入框。

按钮至少 44px 高；输入框在手机为 16px；正文对比度至少 4.5:1。保留可见焦点、标签、禁用、加载、空状态、失败重试和权限反馈。共享 `Sheet` 使用原生 dialog，约束焦点、支持 Escape、关闭后恢复焦点，并处理安全区。动画尊重 prefers-reduced-motion。
