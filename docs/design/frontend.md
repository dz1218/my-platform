# Radio Friday 双端视觉与体验系统

Radio Friday 是中文陪伴聊天、直播与小说阅读网站。桌面采用中性黑灰白的 `theme-graphite`，手机采用暖黑、香槟金及独立页面组合；雨夜摄影继续使用独立场景变量。桌面公共布局与侧栏通过中性明暗渐变分区，登录／注册及独立场景保留各自设计。整个前端使用 **Tailwind CSS v4**。

## 手机触摸与刷新约定

- 文档与页面外框统一以动态视口 `100dvh` 作为最小高度，不用 `100vh` 在浏览器工具栏展开时撑出额外空白。手机根滚动区使用 `overscroll-behavior-y: none`，阻止到顶／到底后的整页回弹露底；长页面仍由文档自然滚动，内层聊天与弹层保留独立滚动，自定义下拉刷新继续处理顶部手势，不通过固定 body 或全局禁止触摸截断内容。
- 手机采用 taste-skill 的 app-screen / True-black flat 方向（seed `53379087`），保留现有暖黑、字体和语义 token；用实色明暗层级、紧凑列表与统一分段控件组织内容。主导航和分段选择使用中性选中面，金色保留给主要操作。普通内容统一 20px 边距并适配左右安全区；交互目标至少 44px，输入文字至少 16px。
- 所有模态入口（共享 Sheet、直播关闭确认、会话设置、认证说明）使用 `useDialogScrollLock`。锁由浏览器文档持有，按打开顺序管理嵌套弹窗；最后一个模态关闭才恢复原样式。触摸／滚轮只允许当前弹窗及其 Select 浮层中仍能滚动的区域消费，避免滚到底后带动背景。非模态桌面会话设置不锁页面。共享 Sheet 保留原生焦点圈定、Escape、遮罩关闭及触发入口焦点恢复；长内容在面板内部滚动；面板高度和底部位置跟随 Visual Viewport，使软键盘弹出后仍能访问内容和操作。
- 陪伴目录、直播大厅、小说书架及我的页面的最近聊天数据支持 `MobilePullToRefresh`。手势从页面顶部开始，先判断方向，整块 main 内容（含页头）随手指阻尼下移，底部导航保持固定；顶部提示位于拉出的空隙中。累计至 64px 后松手才刷新，以 280ms 回弹到 56px 的刷新位置，结果短暂展示后收回；短拉和取消手势直接回弹归位，不发请求。横滑、多指、表单控件、内层滚动区域和弹窗均不触发。刷新期间禁止重复触发，显示进行中／成功／失败反馈，失败保留旧内容并可重试；键盘与读屏有「刷新当前页面」按钮，原页面刷新／失败重试入口继续可用。减少动态效果时取消回弹过渡。
- 刷新复用宿主 Query 或既有直播校准 action，保留筛选、草稿与连接，不重载文档。直播仍遵守 revision 检查，不用较旧的 HTTP 结果覆盖较新的实时快照。聊天记录、直播播放页、阅读正文及编辑／认证表单保留各自滚动手势，不挂载列表下拉刷新。
- 下拉距离、阶段与手势起点属于控件呈现状态，允许局部 React state/ref；定时器、监听器及未完成回调在路由离开或禁用时清理。数据仍在 React Query，业务并发与错误仍由已有领域 owner 管理，不新增持久化状态。
- 滚动边界实现参考 [MDN overscroll-behavior](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/overscroll-behavior)，同时处理内容不足一屏的弹层；不能仅依赖 `overflow: hidden` 或浏览器原生下拉刷新。

## 架构与共享边界

手机网页通过独立 workspace 包与桌面分开开发，仍在同一 Next.js 站点部署。后续小程序采用 Taro + React，复用业务核心并自行实现平台适配与页面；本次不创建小程序应用，不改变后端认证协议。

| 包 | 职责 |
| --- | --- |
| `apps/web` | Next.js 路由、服务端取数/Server Actions、认证、桌面界面、稳定业务宿主和浏览器/LiveKit 资源 |
| `@my-platform/mobile-web` | 手机页面组合、导航、底部操作面板、消息输入和手机专属交互状态 |
| `@my-platform/web-ui` | 共享 Sheet、Select、头像、场景横幅、标题、加载占位和视口订阅 |
| `@my-platform/client-core` | 业务 store 工厂、actions、selectors、校验和注入式服务契约；`/react` 为独立 React 绑定入口 |
| `@my-platform/shared` | 共享业务数据类型与接口契约 |

依赖由应用指向包；UI 包不反向引用应用或 Next.js。导航链接、服务端内容及优化图片通过 props/slots 注入。共享核心使用 Zustand vanilla 和 query-core，不直接调用浏览器资源或导入 LiveKit；平台行为由宿主注入。`pnpm check:client-boundaries` 检查这些边界。

- 同一个 Next.js 工程、同一组路由、登录态和后端 API。根布局负责解析账户；普通主 Tab 复用已解析的账户，详情、阅读与管理页继续负责服务端内容和权限检查，不能为双端视图复制认证或权限判断。
- 业务控制层负责查询、缓存、权限、提交和实时连接；其下才是桌面／手机页面组合。`useCompanionHome`、`useLiveLobby`、`useConversation`、`useLiveRoom` 和 `useLiveVoice` 不随视图切换重新挂载。
- `useViewport` 是客户端页面的统一视口入口：小于 768px 为手机，其余为桌面。服务端与客户端首次渲染均返回未知视口，复杂页面在内容区显示对应布局的加载占位，四个主 Tab 使用内容骨架，公共导航与页面外框保持可用，避免 hydration 不一致或先展示桌面布局。
- `AppShell` 的桌面侧栏与手机底栏是没有业务副作用的导航组件。`BrowsingPages` 稳定宿主按已提交 pathname 直接呈现四个主 Tab：陪伴目录按需挂载后保留，其他三个仅在当前路由挂载并从缓存恢复；主 Tab 的 page/loading 不重复渲染内容或覆盖路由骨架。详情、阅读与编辑继续由实际路由 children 服务端渲染，书架统一使用客户端查询。
- 实时聊天室的连接、草稿和媒体节点位于稳定的组件层级中。手机的成员／连麦面板独立组合，舞台和聊天记录不因横竖屏切换而重建。
- 连麦时默认主播大画面、连麦者右下角小画面，保留小画面内的切换图标，可互换大小画面且不重建媒体节点；不再显示直播框右上角的“切换大小画面”文字按钮。听众设备顺序与主播一致：摄像头在前、麦克风在后。桌面设备按钮位于舞台下方操作栏左侧，连麦时右侧只有一个可展开的“退出”入口，按钮保留原有样式和展开箭头，不显示左侧退出图标；鼠标悬停时向上展开原生 Popover，移出按钮和菜单后延迟收起，跨越两者间隙时保持展开；悬停不抢焦点，点击入口不切换关闭，键盘和触屏仍可展开。菜单区分“退出连麦 / 留在直播间，继续观看”和“退出房间 / 退出当前直播间”，支持键盘导航、Escape、点击外部关闭与焦点恢复。未连麦时仍可直接退出房间。手机设备保留在底部面板，连麦退出与房间退出统一进入右侧“退出”底部面板。获准不会自动开启设备，退出连麦后仍可观看。
- 通用按钮、头像、书封、消息气泡、状态提示和表单字段共享；手机页面信息顺序、导航、筛选和操作面板由 mobile-web 独立组合。连接、会话和媒体元素保留稳定层级，不通过复制后隐藏实现双端页面。

## 客户端状态管理

客户端业务状态优先放在 `packages/client-core/src` 的 Zustand store 中；`apps/web/src/stores` 保留浏览器适配、Provider 和网页交互组合，手机专属交互状态放在 `packages/mobile-web/src/stores`。组织方式参考 [LobeChat 的业务 store 与 slice 组合](https://github.com/lobehub/lobehub/blob/main/src/store/chat/store.ts)：区分初始状态、action、selector 和组合入口；复杂域拆 slice，小型 store 可以同文件组织。业务组件订阅 selector，通过 action 更新状态；组合多个字段的 selector 使用 `useShallow`，避免每次读取返回新对象导致重复渲染。需要在异步回调中读取最新值时使用当前实例的 `getState()`；不得用它代替视图订阅。

业务 action 应包含校验、权限与并发门禁、请求编排、错误恢复、重试 ID、原子状态切换和 Query 缓存更新，不只提供 setter。网络协议放在 services，浏览器／SDK 资源通过适配函数传入 action，不存进 store。组件负责渲染、路由和资源生命周期，避免再用一组 setter 在组件内重建业务流程。

所有业务 store 通过 `createDomainStore` 组合 `subscribeWithSelector`。参考 [LobeChat 的草稿订阅](https://github.com/lobehub/lobehub/blob/main/src/features/ChatInput/hooks/useChatInputDraft.ts)，跨状态联动优先使用 selector subscription：侧栏偏好保存、验证码倒计时、筛选后的查询取消和滚动、身份选择刷新、验证完成后的焦点、关闭房间弹窗、连麦授权撤销、消息滚动和通知过期。订阅在宿主 effect 内绑定并返回 unsubscribe；定时器和 animation frame 一并清理，支持 Strict Mode 重绑。只有需要初始化外部资源时使用 `fireImmediately`；复合 selector 应使用 equalityFn。视图仍使用 `useStore(selector)`，不得通过手动订阅再维护一份 React 状态。用户主动提交仍调用 action，不能由订阅隐式发起继承、创建房间等写操作。

| Store | 管理范围 | 生命周期 |
| --- | --- | --- |
| `app` | 侧栏折叠与客户端布局初始化 | 账户 Provider；只有侧栏偏好写入 localStorage |
| `browse` | 个人页标签、直播搜索与筛选、书架搜索草稿／条件／页码、最近陪伴 URL | 账户 Provider；只保留当前文档内浏览状态 |
| `chat` | 按会话区分的输入草稿 | 账户 Provider；同账户路由切换保留，退出或换账户销毁 |
| `chat/conversation`、`chat/auto-reply`、`chat/preferences` | 连接错误、发送中的消息、失败重试请求 ID、设置提交反馈 | 当前会话；以 conversationId 为 key |
| `auth`、`auth/transition` | 手机验证、注册资料、密码输入、倒计时、字段错误、认证页退出状态 | 当前表单／认证过渡宿主；不持久化 |
| `companion`、`catalog` | 已应用筛选、独立筛选草稿与手机搜索 | 陪伴稳定宿主／筛选编辑器；已应用条件随 Tab 保留，关闭筛选浮层或弹层丢弃未应用草稿 |
| `identity` | 身份选择、确认快照、性别输入 | 当前页面，账户切换时一并销毁；个人页标签由 browse 管理 |
| `live/lobby`、`live/room`、`live/voice`、`live/chat`、`live/stage` | 创建流程、房间会话、媒体状态、连麦、消息、未读与舞台选择 | 当前大厅／房间；以 roomId 为 key，离开／重连清理会话状态；大厅搜索与筛选由 browse 管理 |

Store 由 `useStoreInstance` 在稳定宿主内创建，工厂不启动网络连接或计时器。根 `Providers` 已按 accountId 设置 key；桌面和手机消费同一业务层实例，窗口尺寸变化不会创建第二套 store 或连接。遵循 [Zustand 的 Next.js 实例隔离建议](https://zustand.docs.pmnd.rs/learn/guides/nextjs)，禁止模块级可变账户、表单或房间单例，避免服务端请求间共享数据。React Context 只负责注入 store 实例或导航／动画命令，不另存一份业务状态。

React Query 继续管理角色目录、会话列表、历史消息、自动回复设置、身份继承和房间列表等接口数据；不将查询结果同步复制到 Zustand。URL 中的 `view`、会话和路由信息仍由 Next.js 路由管理。原生表单提交生命周期继续使用 `useActionState` / `useFormStatus`。小说书架由账户作用域 React Query 管理，详情、阅读和管理内容仍由服务端渲染。小说写操作继续使用 Server Action 和原生表单；客户端表单适配器标记书架查询失效，提交完成后再次失效以覆盖写入与提前返回的竞态，不复制详情或章节缓存。

书架采用服务端分页，每页 12 本，按最近更新排序并以 ID 保证同时间记录的顺序稳定。搜索书名、作者或简介，点击搜索或回车提交；应用和清空搜索均回到第一页，输入中文组合期间不发查询。账户作用域 browse 保留搜索草稿、已应用条件和页码，React Query 按条件与页码缓存结果；离开后返回保留浏览位置，写操作使所有书架分页失效。分页按钮移焦并滚动至列表顶部，接口按同一数据库快照返回总数与内容，末页删除后回到最后有效页。搜索无结果与空书架分别提示，刷新失败保留当前页内容。首次进入且没有缓存时显示骨架；搜索与翻页期间保留上一份列表、数量和布局，只在搜索图标位置显示加载反馈，响应完成后更新内容。保留的旧结果不参与当前页码校正，也不写入新条件的缓存；空状态使用实际展示结果的搜索条件，避免清空搜索时短暂显示错误提示。桌面保留书封网格，页头将「书架＋数量」、紧凑搜索框与创建小说排在同一行；搜索通过框内图标或回车提交，不另放搜索按钮。手机保留「书架＋数量／创建小说」同一行与紧凑列表，下一行提供完整宽度的搜索框。分页使用轻量箭头、页码与分隔线，搜索和分页复用语义控件样式，不增加刷新图标。

DOM、WebSocket、LiveKit Room/Track、AbortController、计时器、滚动与焦点快照留在 refs/effects 中，保持原来的关闭和释放路径。允许局部 React 状态的范围是：通用 Select 的展开、选项搜索、键盘活动项及原生有效性；说明弹层、账户菜单与直播离开菜单的显示；手机号遮罩；背景轮播和个人页标签指示条的纯动画状态；瀑布流测量；路由滚动恢复期间的绘制就绪状态；`CompanionChatRoute` 的宿主注册及测量快照展示状态；LiveKit Track 的视图绑定、直播连接占位的延迟说明显示（8 秒后出现，卸载清理计时器）。这些属于控件自身或浏览器资源状态。性别、手机号、密码、筛选值等业务输入由所属 store 控制。

密码、验证码、验证票据、房间令牌和账户草稿只在内存中存在，不进入 localStorage、devtools 或 window 全局。异步结果写回创建它的实例；手机输入版本变化后，旧验证响应不得恢复票据。发送成功只清除与原发送内容一致的草稿，失败重试复用请求 ID。直播消息去重并限制历史长度；断开后清理房间权限、连麦批准、设备状态和消息草稿。

`apps/web/src/app/theme.css` 是唯一 token 入口；`globals.css` 导入 token 并提供共享组件样式，通过 `@source` 扫描 mobile-web 与 web-ui 的 Tailwind 类名。页面优先使用 JSX 的 Tailwind 工具类；共享样式用 `@apply`，功能样式表用 `@reference` 引用全局入口。颜色不得写进业务组件。

桌面 `theme-graphite` 复用相同语义工具类：背景 `#111111`、面板 `#181818`、次级表面 `#242424`、悬停 `#2C2C2C`、选中 `#343434`、边界 `#383838`、控件边界 `#737373`、正文及主操作 `#F5F5F5`、辅助文字 `#A3A3A3`，主操作反色文字为 `#181818`。品牌强调与焦点使用中性灰白，不使用暖白或棕色；公共背景氛围光按统一设计使用低饱和紫色。仅在 768px 起应用，手机继续继承根节点的 `theme-night`。

根节点与局部 `theme-night` 使用同一套变量，不随系统明暗偏好变化。图片使用独立 `photo-*` token，成功、警告、错误使用各自语义色及 soft/line 配套变量，始终配文字说明。

- 字标采用 Georgia（`font-brand`），中文采用苹方／微软雅黑。桌面标题 28–32px，手机标题 24px，正文 14–16px，辅助文字至少 12px；阅读正文 18px、1.9 倍行高、最大宽度 680px。
- 4px 间距体系；控件圆角 10px、卡片 16px、摄影横幅 24px。桌面公共内容容器使用共享 `page-shell`，最大宽度 1280px，在侧栏之外的可用区域内居中；视口达到 1280px 时左右内边距为 64px，较窄视口沿用自适应边距。陪伴、小说和「我的」首页统一使用该容器；直播大厅使用下述通栏例外。侧栏展开宽 236px，收起宽 80px。
- `theme-night` 的金色用于主操作、焦点和少量品牌细节；列表、面板通过实色表面与留白分层，不叠加大面积发光效果。

## 认证与组件状态

### 路由与数据加载

主导航点击后立即高亮目标，并以轻量进度提示表示路由等待，不覆盖或禁用整页内容。URL 提交前的临时状态放在账户作用域的 app store，只有目标地址与递增导航标识，不持久化。Next Link 的 pending 状态负责结束跟踪，旧导航不得清除新导航；实际 `aria-current` 以已提交 URL 为准。缓存命中时不设置最短等待时间；失败、重定向和浏览器历史变化都清理过期状态。重复点击当前 Tab 不重新请求，也不强制置顶。认证关闭动画继续由原宿主管理。

根布局先读取本地会话 Cookie；有会话时将远程账户解析放入 Suspense，等待期间输出正确主题、桌面／手机导航及目标页面的真实展示框架：个人页封面、资料位置与页内 Tab；陪伴、直播及书架的标题、横幅与列表工具栏。账户相关控件在解析完成前禁用，骨架仅落在头像、资料或列表等待区域，不把内容替换成独立的通用账户加载块，也不闪现游客账户入口。启动框架与正常页复用展示组件，不挂载业务查询、账户 store 或实时连接。账户解析完成后将同一用户信息交给按账户 ID 隔离的 Provider，四个一级页面直接复用。访客不请求 `/me`；认证页首次加载继续保留完整外框。

桌面陪伴「最近聊天」侧栏的启动展示与正常页面共用 `RecentConversationsFrame`，保留标题、数量位置、禁用刷新按钮、聊天骨架和底部入口。手机陪伴始终直接显示人物目录，旧 `view=recent` 链接也进入目录；不等待会话列表来选择页面。账户解析、视口初始化和目录请求共用双列人物骨架及相同的搜索栏，不闪出标题、Tab 或单列聊天骨架。

加载按区域设计，四个主 Tab 首次无数据时使用与真实内容对应的骨架：陪伴目录按容器宽度展示头像、资料、介绍和操作占位；直播列表沿用房间卡片列宽与 16:9 封面；书架沿用双列手机／自适应桌面网格与 3:4 书封；「我的」保留封面和个人页 Tab，在头像、姓名、手机号及聊天网格位置显示骨架。账户解析、视口初始化和首次接口等待共用同一套展示组件，避免阶段切换时闪出转圈黑块或空白列表。骨架用共享 `SkeletonRegion` / `SkeletonBlock` 和语义表面色，留在正常文档流内，不覆盖导航、标题、筛选或页内 Tab；加载说明供读屏使用，装饰占位不参与交互，轻微明暗动画在减少动态效果时关闭。详情、阅读、身份、工作台及表单继续保留对应页面结构并使用局部 `LoadingPlaceholder`；聊天在账户启动、路由、资料与消息等待阶段复用聊天外框和消息骨架，已知姓名立即显示；直播连接等待留在连接区。已有缓存直接显示，不因主 Tab 往返或直播后台轮询重新出现骨架；手动刷新仍只在触发按钮显示进度，失败保留内容并在本区域提供重试，不使用虚构进度。

普通主 Tab 查询统一使用 `staleTime: Infinity`、`gcTime: Infinity`，关闭聚焦和网络重连触发的普通列表刷新；每个账户在当前文档内保留 React Query 缓存，不写持久存储。列表提供定向刷新入口，自己的操作通过缓存更新或主动失效反映结果，不调用整站 `router.refresh()`。浏览器刷新重新取数；退出或换账户销毁缓存、浏览状态和滚动快照。最近聊天共用一个账户级 WebSocket，陪伴与「我的」共享列表，HTTP 响应不得覆盖后到的实时快照；聊天连接仍由会话宿主管理。打招呼等待期间离开陪伴后，成功结果仍更新当前账户的会话列表，但不再自动进入聊天；退出账户后，旧操作不得写回缓存或导航。已登录会话的查询返回 401 时，根错误处理合并并发核验，专门请求一次 `/me`：同一账户核验成功直接更新账户查询，页面和导航共享该结果；核验服务暂时失败或返回 403 时保留已有身份，后续操作可再次核验。确认 401 后清除私有缓存并以新文档进入登录页，确认换账户后重新加载文档，销毁旧账户资源。普通业务请求返回 403 只显示当前操作的权限错误，不触发核验或清除账户。

直播大厅和房间详情先通过同源 `/api/live/connection` 获取短期票据，再直连 Go `/api/v1/rooms/socket` 接收共享状态快照，首次连接、断线重连后同步完整状态，不运行固定 5 秒 HTTP 轮询。大厅允许游客订阅公开列表，管理权限按当前账户计算；桌面／手机视图共用连接宿主。推送写入 React Query 前取消旧 HTTP 请求，避免旧响应覆盖新状态；离开页面或账户切换时销毁连接与重连计时器。普通详情读取不触发 LiveKit 核验或清理；手动刷新、主播离开和 SDK 重连完成时使用受限的显式核验接口。服务端另用持久化到期队列补偿遗漏事件；恢复期限来自服务端快照，不由浏览器计时决定关房。主播刷新后设备默认关闭，返回大厅通过关闭确认动作；已接受关闭或查询确认后才能跳转。连麦依赖 LiveKit 属性和权限事件更新，进入、重连与用户操作时进行权威查询，不定时刷新。创建和关闭仍原子更新缓存，直播间标题来自详情快照。小说详情认证与内容保持并行；写操作返回书架后定向更新。聊天入口复用已有 match，悬停／聚焦只预取 HTTP 消息。

陪伴「打个招呼」按人物 ID 记录等待状态，只有被点击卡片的按钮禁用并在中央显示 18px 细圆环，900ms 匀速旋转，不添加可见等待文案或其他动效；保留原按钮尺寸、主题颜色和清晰度，减少动态效果时圆环静止，读屏通过 `aria-busy` 和隐藏说明识别状态。等待状态优先于已创建会话，从请求开始持续到路由提交，中途不闪出「继续聊天」，返回目录后才显示正常会话入口；失败恢复可操作状态。其他人物、筛选与最近聊天保持可用。同一人物等待期间不重复提交，不同人物可以分别请求。连续打招呼时仅最后一次导航意图允许进入聊天，较早的成功结果仍更新会话缓存；较早的失败不覆盖当前操作反馈，每个请求结束只清理自己的请求状态。进入页面的等待状态由宿主在离开目录时清理，新的聊天意图会替换旧的进入状态。

直播房间刷新使用固定区域逐步就绪的布局：账户解析、路由等待、房间信息和媒体连接共用相同的标题栏、舞台、操作栏与聊天区域尺寸。播放器使用 `theme.css` 的 `media-canvas` 黑色底色，等待时中央只有一个小型 loading，不显示装饰图标、大标题、说明或伪进度；状态说明供读屏使用。未知标题和操作显示简单骨架，聊天等待时保留空白消息区和输入框占位，不模拟消息。房间标题、媒体与聊天各自就绪后原位显示，不互相阻塞，不设最短等待时间；已有画面和消息在重连时继续保留。取消连接放在原有操作栏，错误和重试沿用原路径。手机首屏保持沉浸布局和相同标题高度，减少动态效果时 loading 静止。

桌面直播大厅按参考图使用通栏布局，作为公共 `page-shell` 最大宽度的局部例外：在侧栏外铺满可用宽度，左右留 32–40px。不显示独立的「直播大厅」标题行，仅保留读屏标题；顶部工具栏左侧为状态筛选，右侧依次为深色搜索框和白色「我要开播」按钮，控件统一为 44px 高，窄桌面允许工具栏分行，不显示摄影横幅、目录副标题、工具栏分隔线或常驻创建面板。空列表仅显示两侧短线、声波图标和「暂无直播间」，在剩余视口内居中偏下；筛选或搜索无结果也统一显示「暂无直播间」，不再显示「查看全部直播间」按钮，用户通过顶部筛选和搜索调整条件。颜色复用 `theme-graphite` 语义 token，手机沿用独立布局。首次查询期间禁用开播入口并保留房间骨架；确认已有房间后入口显示「我的直播间」。桌面复用共享 `Sheet` 的居中模式，创建弹窗宽 520px，使用 24px 圆角和 32px 水平留白；保留既有局部毛玻璃：近实色深灰底、24px 背景模糊、极淡斜向高光和细亮边，遮罩轻微模糊大厅内容，颜色与投影统一来自 theme.css。标题「今晚，开场」使用 24px 半粗字重，下方一句「给今晚的相遇，起一个名字。」；黑胶唱片复用 `LiveRecordArt`，与输入同步的房间名、当前主持人构成房间预览，未填写时明确呈现占位文案，长名称最多两行。表单标签与实际输入长度 / 100 同排，输入框高 48px，聚焦保留清晰轮廓。下方提供三个可点选的名称灵感，点击只更新同一 Zustand 草稿并聚焦输入框；不引入新的业务状态。底部说明摄像头和麦克风默认关闭，右下角保留轻量取消按钮与白底创建按钮，等待时禁用表单并显示创建状态，错误就近呈现。按钮至少 44px 高，悬停使用表面与文字颜色；弹窗短屏内部滚动。手机保留原有底部表单与主题，同一草稿跨视口保留。开播按钮高 44px、14px 字号，搜索聚焦通过深色表面变化反馈，不出现外圈粗边框。创建成功自动关闭弹窗并更新列表；已有房间入口直接进入房间，不打开成功确认面板。失败保留草稿、错误提示、Escape 关闭和焦点恢复。桌面和手机均以「直播中 (n)」「准备中 (n)」显示真实分类数量，桌面卡片只移除直播间名称下方的人数行，封面右下角的人数图标与数字始终保留（包括 0）；手机沿用原布局。

滚动、可见内容锚点与焦点快照由账户作用域稳定宿主的 refs 保存，首次访问置顶，切 Tab 与前进后退恢复。先在 `useLayoutEffect` 中同步恢复滚动；尺寸变化或需要后续测量校正时，仅临时隐藏内容宿主，位置稳定后显示，导航始终可用。陪伴目录在恢复期间暂停自动分页，隐藏期间保留上次的桌面／手机呈现。同一视口恢复原位置；尺寸变化时，陪伴目录、书架、最近聊天和直播列表优先恢复原内容锚点。普通列表通过稳定的 `data-browse-anchor` 标识内容，快照只保存标识和偏移，不持有卸载后的 DOM；内容已移除时回退到合法范围内的原滚动位置。URL 参数仍由路由管理，主导航回陪伴保留原浏览地址与滚动快照；旧 `view` 参数不再切换手机内容。聊天房间、LiveKit、认证和编辑表单不纳入页面保活，不因保留浏览状态延长连接或敏感草稿生命周期。

认证轮播共享一套场景与计时器，用 picture/source 在 760px 分界选择现有手机／桌面素材，首张完成后只预载下一张。允许其局部 React 状态保存场景、已请求／已加载图片和减少动画偏好，均属于动画与浏览器资源状态；不保存业务输入。减少动画时停止自动轮播，手动切换仍可用。

登录／注册延续原有摄影和布局，统一消费暖黑金色 token。保留 5 秒场景轮播、手动选择、减少动态效果，以及原有手机背景；不改认证和身份流程。注册先验证手机号，再设置密码、昵称和性别。

登录与注册共用 `(auth)` 路由布局，客户端切换时只替换表单，外框、品牌与轮播保持挂载，场景及播放进度持续。认证页在首屏加载时也不进入公共侧栏布局。外框右上角提供 44px 关闭入口，关闭后以访客身份进入陪伴首页，并替换历史记录，避免返回时重新打开刚关闭的认证页。关闭采用约 380ms 的登录页轻微缩小、淡出与首页原位淡入动画。等待实际公共布局挂载并恢复侧栏收起状态后再开始过渡，不对首页及包含固定导航的容器施加缩放或位移；不支持视图过渡时同样使用首页原位淡入，减少动态效果时直接切换。完成后将焦点移至首页主内容。桌面外框高度由视口决定，表单内容超出时只滚动左栏；手机继续使用原有随内容展开的布局。

所有页面和组件的 hover 均不得显示下划线，包括导航、普通链接、按钮、帮助和说明入口。使用文字色、背景色或边框色提供悬停反馈，保留可见键盘焦点；不要添加 `hover:underline` 或通过伪元素模拟悬停下划线。

职业和性别下拉选择统一复用 `components/select.tsx`，不各自实现菜单。可见控件使用主题化按钮和 listbox，不使用原生 `<select>` 弹出系统菜单；隐藏的原生字段仅用于表单提交与必填校验。菜单通过 Popover 进入浏览器顶层，继承所在区域的主题 token，并按可用视口定位和限制高度，避免被滚动容器或 Sheet 裁切。长职业列表支持搜索和内部滚动；保留方向键、Enter、Escape、Tab、选中标记、点击外部关闭及焦点恢复。验收必须展开菜单，覆盖再次打开、应用筛选后的重建、刷新和手机弹层场景，不能只检查收起时的输入框。

所有文本输入、搜索、数字输入、textarea 和 Select 触发器统一使用 10px 圆角、1px 语义边框与实色表面。独立字段使用 `input-field`，带图标、区号、验证码操作或发送按钮的组合输入使用 `input-group`，由外框显示焦点；内部编辑区不再叠加轮廓。特性样式通过 `@apply field-surface` / `field-focus` 复用同一规则。鼠标与键盘聚焦均显示焦点色边框和 3px、15% 透明度的同色外圈，颜色继承场景 token；错误字段使用危险色边框及同色焦点外圈。按钮保留独立键盘焦点，自动填充保留焦点外圈。

按钮至少 44px 高；输入框在手机为 16px；正文对比度至少 4.5:1。保留可见焦点、标签、禁用、加载、空状态、失败重试和权限反馈。共享 `Sheet` 使用原生 dialog，约束焦点、支持 Escape、关闭后恢复焦点，并处理安全区。动画尊重 prefers-reduced-motion。

## 直播首页与搜索入口

## 陪伴记忆

陪伴会话以模拟真人私聊为准。普通聊天页头只呈现对方身份，不常驻账户机制和 AI／真人协作说明；平台身份说明仍保留在原有说明入口。等待回复时不展示生成转圈、排队状态或“正在回复”，也不将后台任务伪装成“正在输入”。自己消息的发送失败与重试反馈继续保留。

桌面、手机的用户记忆管理均默认收起，从页头更多按钮打开；关闭后回到聊天，宽屏也不自动展开。只有继承者的回复工作台保留宽屏管理侧栏。记忆授权、查看、编辑、删除与候选确认仍在设置里完成；不因为沉浸体验改变用户授权。

陪伴会话设置增加独立用户记忆区域，权限使用 `canManageMemory`，不依赖继承者 `canManage`。手机使用 `mobile-web/memory` 呈现，桌面复用 `web-ui/memory-panel`，共享 `client-core/chat/memory` 的会话级 Zustand 工厂管理编辑、确认和并发；记忆及授权仍在 React Query。开关等待时禁用相关操作，失败保留草稿，关闭记忆仍可查看与删除；切换账户/会话销毁旧 owner。复用原 Dialog 的焦点与滚动锁，以及 Tailwind v4 语义 token。

## 密码管理

找回密码沿用认证场景的外框、轮播和手机布局；修改密码入口位于我的页面账号信息区，桌面居中、手机底部展开，复用共享 Sheet 的滚动锁、焦点和安全区。手机与桌面共享同一个表单 owner，跨断点不丢失草稿；短信找回直接在当前 Sheet 切换，切换时销毁上一种验证方式的敏感草稿，关闭后再次打开回到原密码修改。密码输入提示沿用注册页的占位文案。`client-core/auth` 的密码 store 管理字段、短信阶段、限流倒计时与错误；Server Actions 管理提交，密码、验证码、票据不持久化。关闭或离开时清空敏感字段，提交失败保留输入。成功后完整文档导航到登录页，所有旧设备需要重新登录，旧版本直播间进入现有关房与重试流程。
