# Radio Friday 双端视觉与体验系统

Radio Friday 是中文陪伴聊天、直播与小说阅读网站。桌面采用中性黑灰白的 `theme-graphite`，手机保留暖黑、香槟金及现有页面组合；雨夜摄影继续使用独立场景变量。桌面公共布局与侧栏通过中性明暗渐变分区，登录／注册及独立场景保留各自设计。整个前端使用 **Tailwind CSS v4**。

## 架构与共享边界

- 同一个 Next.js 工程、同一组路由、登录态和后端 API。服务端页面继续负责认证和服务端内容，不能为双端视图复制认证或权限判断。
- 业务控制层负责查询、缓存、权限、提交和实时连接；其下才是桌面／手机页面组合。`useCompanionHome`、`useLiveLobby`、`useConversation`、`useLiveRoom` 和 `useLiveVoice` 不随视图切换重新挂载。
- `useViewport` 是客户端页面的统一视口入口：小于 768px 为手机，其余为桌面。服务端与客户端首次渲染均返回未知视口，复杂页面先显示轻量骨架，避免 hydration 不一致或先展示桌面布局。
- `AppShell` 的桌面侧栏与手机底栏是没有业务副作用的导航组件。内容只渲染一份；小说正文、书封、账户信息等保持服务端渲染，通过内容组件和布局规则复用。
- 实时聊天室的连接、草稿和媒体节点位于稳定的组件层级中。手机的成员／连麦面板独立组合，舞台和聊天记录不因横竖屏切换而重建。
- 通用按钮、头像、书封、消息气泡、状态提示和表单字段共享；页面信息顺序、导航、筛选和操作面板可独立组合。

## 客户端状态管理

客户端业务状态优先放在 `apps/web/src/stores` 的 Zustand store 中。组织方式参考 [LobeChat 的业务 store 与 slice 组合](https://github.com/lobehub/lobehub/blob/main/src/store/chat/store.ts)：区分初始状态、action、selector 和组合入口；复杂域拆 slice，小型 store 可以同文件组织。业务组件订阅 selector，通过 action 更新状态；组合多个字段的 selector 使用 `useShallow`，避免每次读取返回新对象导致重复渲染。需要在异步回调中读取最新值时使用当前实例的 `getState()`；不得用它代替视图订阅。

业务 action 应包含校验、权限与并发门禁、请求编排、错误恢复、重试 ID、原子状态切换和 Query 缓存更新，不只提供 setter。网络协议放在 services，浏览器／SDK 资源通过适配函数传入 action，不存进 store。组件负责渲染、路由和资源生命周期，避免再用一组 setter 在组件内重建业务流程。

所有业务 store 通过 `createDomainStore` 组合 `subscribeWithSelector`。参考 [LobeChat 的草稿订阅](https://github.com/lobehub/lobehub/blob/main/src/features/ChatInput/hooks/useChatInputDraft.ts)，跨状态联动优先使用 selector subscription：侧栏偏好保存、验证码倒计时、筛选后的查询取消和滚动、身份选择刷新、验证完成后的焦点、关闭房间弹窗、连麦授权撤销、消息滚动和通知过期。订阅在宿主 effect 内绑定并返回 unsubscribe；定时器和 animation frame 一并清理，支持 Strict Mode 重绑。只有需要初始化外部资源时使用 `fireImmediately`；复合 selector 应使用 equalityFn。视图仍使用 `useStore(selector)`，不得通过手动订阅再维护一份 React 状态。用户主动提交仍调用 action，不能由订阅隐式发起继承、创建房间等写操作。

| Store | 管理范围 | 生命周期 |
| --- | --- | --- |
| `app` | 侧栏折叠与客户端布局初始化 | 账户 Provider；只有侧栏偏好写入 localStorage |
| `chat` | 按会话区分的输入草稿 | 账户 Provider；同账户路由切换保留，退出或换账户销毁 |
| `chat/conversation`、`chat/auto-reply`、`chat/preferences` | 连接错误、发送中的消息、失败重试请求 ID、设置提交反馈 | 当前会话；以 conversationId 为 key |
| `auth`、`auth/transition` | 手机验证、注册资料、密码输入、倒计时、字段错误、认证页退出状态 | 当前表单／认证过渡宿主；不持久化 |
| `companion`、`catalog` | 已应用筛选、默认标签、独立筛选草稿与手机搜索 | 当前页面／编辑器；关闭筛选弹层丢弃未应用草稿 |
| `identity`、`account` | 身份选择、确认快照、性别输入、个人页标签 | 当前页面，账户切换时一并销毁 |
| `live/lobby`、`live/room`、`live/voice`、`live/chat`、`live/stage` | 大厅筛选和创建流程、房间会话、媒体状态、连麦、消息、未读与舞台选择 | 当前大厅／房间；以 roomId 为 key，离开／重连清理会话状态 |

Store 由 `useStoreInstance` 在稳定宿主内创建，工厂不启动网络连接或计时器。根 `Providers` 已按 accountId 设置 key；桌面和手机消费同一业务层实例，窗口尺寸变化不会创建第二套 store 或连接。遵循 [Zustand 的 Next.js 实例隔离建议](https://zustand.docs.pmnd.rs/learn/guides/nextjs)，禁止模块级可变账户、表单或房间单例，避免服务端请求间共享数据。React Context 只负责注入 store 实例或导航／动画命令，不另存一份业务状态。

React Query 继续管理角色目录、会话列表、历史消息、自动回复设置、身份继承和房间列表等接口数据；不将查询结果同步复制到 Zustand。URL 中的 `view`、会话和路由信息仍由 Next.js 路由管理。原生表单提交生命周期继续使用 `useActionState` / `useFormStatus`。小说页面以服务端渲染和原生表单为主，不人为添加客户端数据副本。

DOM、WebSocket、LiveKit Room/Track、AbortController、计时器、滚动与焦点快照留在 refs/effects 中，保持原来的关闭和释放路径。允许局部 React 状态的范围是：通用 Select 的展开、选项搜索、键盘活动项及原生有效性；说明弹层和账户菜单的显示；手机号遮罩；背景轮播动画；瀑布流测量；LiveKit Track 的视图绑定。这些属于控件自身或浏览器资源状态。性别、手机号、密码、筛选值等业务输入由所属 store 控制。

密码、验证码、验证票据、房间令牌和账户草稿只在内存中存在，不进入 localStorage、devtools 或 window 全局。异步结果写回创建它的实例；手机输入版本变化后，旧验证响应不得恢复票据。发送成功只清除与原发送内容一致的草稿，失败重试复用请求 ID。直播消息去重并限制历史长度；断开后清理房间权限、连麦批准、设备状态和消息草稿。

## 设计变量

`apps/web/src/app/theme.css` 是唯一 token 入口；`globals.css` 导入 token 并提供共享组件样式。页面优先使用 JSX 的 Tailwind 工具类；共享样式用 `@apply`，功能样式表用 `@reference` 引用全局入口。颜色不得写进业务组件。

下表为手机及现有 `theme-night` 的变量：

| 用途 | 值 | 工具类 |
| --- | --- | --- |
| 页面背景 | `#1B1B19` | `bg-canvas` |
| 面板 | `#141413` | `bg-panel` |
| 次级表面 | `#262623` | `bg-surface-soft` |
| 悬停／选中表面 | `#33322E` / `#3B3933` | `bg-surface-hover` / `bg-surface-selected` |
| 正文 | `#F3F1EC` | `text-ink` |
| 次要文字 | `#B9B5AD` | `text-muted` |
| 提示文字 | `#AAA59C` | `text-faint` |
| 分隔线／控件边界 | `#41403B` / `#777269` | `border-line` / `border-control` |
| 主操作／反色文字 | `#DFBC89` / `#262522` | `bg-action text-on-action` |
| 品牌／焦点 | `#DFBC89` | `text-accent outline-focus` |
| 阅读背景 | `#1D1C19` | `bg-reading` |

桌面 `theme-graphite` 复用相同语义工具类：背景 `#111111`、面板 `#181818`、次级表面 `#242424`、悬停 `#2C2C2C`、选中 `#343434`、边界 `#383838`、控件边界 `#737373`、正文及主操作 `#F5F5F5`、辅助文字 `#A3A3A3`，主操作反色文字为 `#181818`。品牌强调与焦点使用中性灰白，不使用暖白或棕色；公共背景氛围光按统一设计使用低饱和紫色。仅在 768px 起应用，手机继续继承根节点的 `theme-night`。

根节点与局部 `theme-night` 使用同一套变量，不随系统明暗偏好变化。图片使用独立 `photo-*` token，成功、警告、错误使用各自语义色及 soft/line 配套变量，始终配文字说明。

- 字标采用 Georgia（`font-brand`），中文采用苹方／微软雅黑。桌面标题 28–32px，手机标题 24px，正文 14–16px，辅助文字至少 12px；阅读正文 18px、1.9 倍行高、最大宽度 680px。
- 4px 间距体系；控件圆角 10px、卡片 16px、摄影横幅 24px。桌面公共内容容器使用共享 `page-shell`，最大宽度 1280px，在侧栏之外的可用区域内居中；视口达到 1280px 时左右内边距为 64px，较窄视口沿用自适应边距。陪伴、直播大厅、小说和「我的」首页统一使用该容器，侧栏展开宽 236px，收起宽 80px。
- `theme-night` 的金色用于主操作、焦点和少量品牌细节；列表、面板通过实色表面与留白分层，不叠加大面积发光效果。
- 摄影使用现有素材。`SceneBanner` 负责桌面 260px 横幅和紧凑场景；手机最近聊天没有横幅。新增场景没有自动轮播。
- 通用图标使用 lucide-react，1.75–2px 线宽；`RadioMark` 使用 AudioLines。桌面主导航使用自绘 28px SVG 图标：爱心对话、收音机、书签书页、圆形账户；统一继承语义文字色，手机保留现有图标。

## 双端页面与导航

| 页面 | 桌面 | 手机 |
| --- | --- | --- |
| 陪伴 | 场景横幅、目录、最近聊天侧栏 | 最近聊天／发现朋友标签，只有发现页有紧凑摄影 |
| 人物目录 | 常驻筛选与多列虚拟列表 | 单列虚拟列表、搜索、筛选底部弹层 |
| 聊天 | 对话与宽屏设置侧栏 | 全屏对话、底部输入、全高设置面板 |
| 直播大厅 | 场景横幅、房间目录、创建面板 | 列表优先，开播入口打开底部表单 |
| 直播房间 | 舞台与互动侧栏 | 舞台上方、聊天下方，成员和连麦使用弹层 |
| 小说 | 摄影与书封网格 | 紧凑场景、双列书架 |
| 阅读 | 居中正文 | 沉浸正文、返回与章节操作 |
| 我的与身份 | 月夜海面封面、最近聊天与身份标签、会话网格 | 紧凑封面、同一标签、单列会话 |

「我的」采用宽幅个人主页，使用公共内容容器。冷色月夜海面作为页面顶部背景，横向铺满内容视口、贴顶，无圆角、外框或投影。通过 alpha mask 向下透明渐隐，桌面左侧也淡入侧栏背景，露出页面自身底色，不叠加不匹配的黑色底板。资料区位于背景下半部，头像和文字使用常规语义 token；手机号隐藏时显示划线眼睛，明文时显示普通眼睛，按钮可访问名称描述下一步操作；不重复展示「我的」标题。手机保留原暖色主题。Tab 与下方内容直接使用页面背景，不加外层底色、边框或阴影，导航和内容共用 16px／24px 内边距，内部会话入口使用轻量次级表面而非多重边框。会话卡片与 AI 身份入口悬停时保持底色，通过贴近边缘的低饱和青灰、淡紫微光反馈，光晕半径 8px、透明度 6%–7%，避免明显亮框与大范围扩散，使用 theme.css 中的共享 shadow-card-hover-glow token，200ms 渐入渐出；键盘聚焦同样显示柔光并保留焦点轮廓，减少动态效果时取消过渡。通过「最近聊天」「AI 身份」两个等宽、同字重的标签切换内容；选中项使用 3px 的青蓝—紫色—粉色渐变滑动下划线及轻微柔光，渐变与柔光 token 统一定义在 theme.css；这是用户指定的局部彩色强调，其他桌面控件保持黑灰白。不显示独立胶囊底色。切换时指示条在两个标签间移动，并带短暂拉伸、轻微回弹；首次加载不播放动画，快速反向切换从当前位置接续，减少动态效果时即时定位。下划线仅表示选中状态，悬停只改变文字色；支持方向键、Home/End 与可见焦点。面板外沿与资料区使用同一个 page-shell 对齐线。最近聊天从现有 matches 接口读取，在内容标题旁以紧凑圆角徽标显示真实数量，使用等宽数字、低对比底色和细边框，并展示会话入口，保留加载、失败重试、空状态。发现入口仅保留内容标题右侧的「认识新朋友」，封面与空状态不再重复提供聊天／发现按钮。AI 身份区域沿用角色选择、继承规则和最终确认流程；已继承时展示真实角色与回复入口。不添加虚构的粉丝、等级、作品数或无功能的设置入口。平台互动说明和退出登录保留在账户菜单中。桌面侧栏在登录后保留四个直接入口；访客只显示陪伴、直播和小说，账户入口集中在底部的「登录 / 注册」。导航行高至少 56px、胶囊圆角、16px 半粗文字；选中态使用中性表面及底部轻微柔光，不增加多级菜单。桌面侧栏底部不加分隔线，账户入口距离视口底部 32px，只保留一个账户入口：40px 实色头像配姓名和「账户与身份」，不显示箭头。鼠标悬停 120ms 后打开右侧约 300px 宽的账户浮层，点击、触控和键盘也可展开，不跳转陪伴页；浮层使用原生 auto Popover 进入浏览器顶层，避开侧栏滚动裁切，浮层左边与账户入口右边保持 8px 间距，底边严格对齐账户行，最大高度按账户行底边至视口顶部的可用空间计算，短屏内部滚动。「我的」（/me）保留在主导航，浮层只包含「拥有一个 AI 身份」（/choose-identity，说明为「以角色身份回复其他用户」）、平台互动说明和退出登录；已继承身份时第一项显示角色名字及「以此身份回复消息」，进入 /operator。继承页面继续保留不可更换等规则和最终确认。退出登录复用现有服务端 action。悬停打开不抢焦点，鼠标离开入口和浮层后延迟 250ms 关闭，经过两者间隙不会立即收起；点击或键盘打开时聚焦首个链接，Escape 关闭，焦点原本在浮层内时返回触发按钮，点击外部、焦点离开、点击链接、切换路由或调整视口时关闭。悬停用表面和文字颜色反馈，不使用下划线。长名称省略但保留完整可访问名称。

短屏侧栏允许滚动。顶部品牌图标是展开／收起按钮，文字字标仍链接首页；状态保存在本地，切换路由和刷新后保留；内容区、聊天浮层和直播提示共享侧栏宽度变量。桌面侧栏为 `bg-canvas`，非沉浸内容区从左缘的 `#111111` 在 160px 内渐变至 `#161616`，通过柔和明暗差分区，不显示中间竖分隔线。收起后底部只显示一个居中的账户头像，44px 圆形点击区内使用 32px 头像；悬停时直接打开同一账户浮层，不再叠加名称浮签；保留完整可访问名称和键盘打开方式。手机导航保持原样，切换至手机宽度时关闭桌面浮层。


平台互动说明从账户菜单原地打开：先收起账户浮层，再显示共享说明弹窗，不切换路由。桌面弹窗居中、宽 640px，默认呈现约 430–500px 高的紧凑面板；手机为底部弹层。默认用三条短说明呈现 AI／真人回复、继承者可查看历史聊天、身份继承规则，图标只做轻量辅助，不套卡片。标题和操作区不加横向分隔线，底部左侧为「查看完整说明」，右侧为紧凑的次要按钮「我知道了」。完整说明在同一面板内切换展示，可返回要点；详细内容保留全部原说明，内部滚动。支持关闭按钮、Escape、点击遮罩关闭；关闭后恢复页面滚动位置与触发入口焦点，账户菜单来源则恢复到账户按钮。弹窗挂载到浏览器顶层，独立于隐藏的账户浮层和桌面侧栏；手机沿用原主题，桌面使用 graphite 变量。登录／注册和独立 /privacy 页面复用同一份分节内容，独立路由仍支持直接访问。

手机公共导航为底部四项：陪伴、直播、小说、我的。顶部由各页面呈现标题和动作，不重复堆放全局品牌栏。普通页面为底栏及安全区预留空间。

陪伴、直播大厅、小说、我的四个桌面首页及非沉浸公共页面共用同一个背景层：右侧为极淡的低饱和紫色斜向渐变，不使用有明显中心的圆形光斑。主色 `#79649C` 的峰值透明度约 7%，辅助色 `#695681` 约 3%，以宽幅平滑过渡避免亮色团块与深色卡片产生割裂。24 秒小幅往返移动；进入页面即处于移动阶段，左缘渐隐以保持与侧栏衔接。效果固定在右侧视口、位于内容下方，跟随侧栏宽度，不接收点击，不改变布局；聊天、直播房间和章节阅读不叠加。颜色统一放在 `theme.css`；仅使用 CSS transform 动画，不使用粒子、视频、模糊滤镜或鼠标跟随。手机隐藏，系统开启减少动态效果时保留静态渐变。

以下页面隐藏手机公共导航：`/chat/:id`、`/operator?id=…`、`/live/:id`、章节阅读页。编辑页不属于阅读沉浸页面。桌面保留侧栏。每个沉浸页面都提供返回入口。

- 未登录首次访问 `/` 进入登录页，关闭后进入 `/companion` 陪伴首页；已登录用户直接进入首页，未完成身份引导的用户继续引导。访客在首页可浏览、筛选角色目录，手机访客默认显示发现朋友。桌面「登录 / 注册」位于左侧栏底部，使用 48px 高的轻量账户入口，默认无边框和底色，悬停显示柔和胶囊背景；20px 登录图标搭配 14px 中等字重文字。「平台互动说明」作为页脚辅助文字入口，以 12px 灰色文字与登录文字左边线对齐，展开时不显示图标，无边框及悬停背景；悬停仅提亮文字，不使用下划线。点击区域按文字宽度、44px 高度设置，距视口底部 32px。登录与主导航共用 20px 水平内边距、28px 图标槽和 16px 图文间距；说明入口左偏移 64px 对齐文字，保留可见键盘焦点。收起侧栏后，两项各保留居中的 44px 图标入口；手机保留四项导航和首页顶部登录入口。访客不请求聊天记录或连接账户实时通道，点击打招呼或登录入口后进入登录页；已登录用户继续现有身份引导流程。退出登录后清除会话并返回陪伴首页，显示访客状态。
- 直接访问 `/companion`、点击主导航「陪伴」或「认识新朋友」时，无论身份引导是否完成都进入陪伴首页，不强制跳转身份选择，也不自动标记引导完成。注册、登录和根路由保留原有身份引导；之后仍可从「我的」主动选择 AI 身份。
- 陪伴支持 `view=recent|discover`。已登录且无指定值时在最近会话加载成功后选择默认标签：有会话选最近聊天，无会话选发现。自动选择只发生一次，手动标签通过浏览器历史记录保留，不受后台轮询影响。
- 筛选弹层打开时读取已应用值；应用后关闭，重置只修改弹层草稿，关闭时丢弃未应用值。手机姓名搜索独立提交。
- 陪伴目录保留虚拟化、加载更多、过滤状态。路由拦截保持目录挂载，进入聊天暂停后台目录操作，返回恢复目录锚点、滚动与焦点。
- 手机聊天回车换行、按钮发送；桌面 Enter 发送、Shift+Enter 换行。中文输入法组合期间不发送。发送失败保留草稿和原有重试逻辑。
- 聊天处理动态视口和底部安全区；连接与草稿不随视口变化重置。媒体节点保持稳定，不能复制两份舞台再用 CSS 隐藏其中一份。
- 小说书封仅对真实标题与作者做排版，不新增封面数据。身份继承保留选择、确认、跳过及本账户／AI 身份区别。
- 身份选择页采用单列布局：返回我的、标题说明、紧凑本账户摘要、身份目录、底部继续入口。账户摘要不加外框，桌面将账户与继承须知横向排在同一行，明确本账户始终保留，须知原地展开。桌面筛选使用轻量工具栏，宽屏将姓名、可搜索职业、年龄与操作放在一行；身份目录最多三列，复用虚拟瀑布流，卡片使用实色表面，仅悬停、聚焦或选中时强调边界。手机保留独立搜索和筛选弹层、单列身份卡片与原主题。无身份且无筛选条件时隐藏筛选表单，使用居中空状态；筛选无结果时保留筛选并提供清除条件。选择身份后使用共享 Sheet：桌面居中确认、手机底部确认，不跳到长列表末尾；确认继续明确唯一性、不可更换规则和本账户保留，选择卡片不直接发起继承。

## 认证与组件状态

### 路由与数据加载

主导航点击后立即高亮目标并显示对应页面骨架；URL 提交前的临时状态放在账户作用域的 app store，只有目标地址与递增导航标识，不持久化。Next Link 的 pending 状态负责结束跟踪，旧导航不得清除新导航；实际 `aria-current` 以已提交 URL 为准。骨架覆盖期间旧内容保持挂载但不可交互，路由提交后由路由 loading 或数据区域 Suspense 接续。缓存命中时不设置最短等待时间。导航、失败重试、重定向和浏览器历史变化都清理过期状态；认证关闭动画继续由原宿主管理。

根布局只先读取本地会话 Cookie；有会话时，远程账户解析放入 Suspense 并显示无账户信息的启动骨架，Provider 继续按账户 ID 隔离。访客直接输出页面，不请求 `/me`，认证页在 hydration 前也保留完整外框。主要路由及聊天拦截分支都有 loading；认证 loading 只替换表单。列表首次请求使用共享骨架，后台刷新保留已有内容。骨架使用语义 token、响应式布局和减少动画规则，不使用虚构进度。

直播 SSR 首批数据携带实际获取时间，查询新鲜期为 5 秒，保留 5 秒轮询和过期后的聚焦刷新；创建和关闭仍原子更新缓存。直播间标题复用该缓存，缺失时后台取列表，不阻塞加入房间。小说认证与内容并行；聊天入口复用已有 match，悬停／聚焦只预取 HTTP 消息，实时连接仍由会话宿主创建。

认证轮播共享一套场景与计时器，用 picture/source 在 760px 分界选择现有手机／桌面素材，首张完成后只预载下一张。允许其局部 React 状态保存场景、已请求／已加载图片和减少动画偏好，均属于动画与浏览器资源状态；不保存业务输入。减少动画时停止自动轮播，手动切换仍可用。

登录／注册延续原有摄影和布局，统一消费暖黑金色 token。保留 5 秒场景轮播、手动选择、减少动态效果，以及原有手机背景；不改认证和身份流程。注册先验证手机号，再设置密码、昵称和性别。

登录与注册共用 `(auth)` 路由布局，客户端切换时只替换表单，外框、品牌与轮播保持挂载，场景及播放进度持续。认证页在首屏加载时也不进入公共侧栏布局。外框右上角提供 44px 关闭入口，关闭后以访客身份进入陪伴首页，并替换历史记录，避免返回时重新打开刚关闭的认证页。关闭采用约 380ms 的登录页轻微缩小、淡出与首页原位淡入动画。等待实际公共布局挂载并恢复侧栏收起状态后再开始过渡，不对首页及包含固定导航的容器施加缩放或位移；不支持视图过渡时同样使用首页原位淡入，减少动态效果时直接切换。完成后将焦点移至首页主内容。桌面外框高度由视口决定，表单内容超出时只滚动左栏；手机继续使用原有随内容展开的布局。

所有页面和组件的 hover 均不得显示下划线，包括导航、普通链接、按钮、帮助和说明入口。使用文字色、背景色或边框色提供悬停反馈，保留可见键盘焦点；不要添加 `hover:underline` 或通过伪元素模拟悬停下划线。

职业和性别下拉选择统一复用 `components/select.tsx`，不各自实现菜单。可见控件使用主题化按钮和 listbox，不使用原生 `<select>` 弹出系统菜单；隐藏的原生字段仅用于表单提交与必填校验。菜单通过 Popover 进入浏览器顶层，继承所在区域的主题 token，并按可用视口定位和限制高度，避免被滚动容器或 Sheet 裁切。长职业列表支持搜索和内部滚动；保留方向键、Enter、Escape、Tab、选中标记、点击外部关闭及焦点恢复。验收必须展开菜单，覆盖再次打开、应用筛选后的重建、刷新和手机弹层场景，不能只检查收起时的输入框。

按钮至少 44px 高；输入框在手机为 16px；正文对比度至少 4.5:1。保留可见焦点、标签、禁用、加载、空状态、失败重试和权限反馈。共享 `Sheet` 使用原生 dialog，约束焦点、支持 Escape、关闭后恢复焦点，并处理安全区。动画尊重 prefers-reduced-motion。
